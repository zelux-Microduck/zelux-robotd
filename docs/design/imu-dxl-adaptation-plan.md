### 已确认的硬件事实

- 当前安装型号为 `qingmu-a1`，使用 `others/IMU-DXL` 所述接入方式，与舵机共享 TTL 总线；当前现场协议已确认为飞特。

- 以下方向均以机器人正常站立为基准；统一机体坐标正方向为前（X）、左（Y）、上（Z）。表中板卡轴采用各型号的板卡坐标定义，不按照片左右或插头方向猜测。

| 型号 | 板卡 +X 指向 | 板卡 +Y 指向 | 板卡 +Z 指向 | 固定安装方式 | 协议确认情况 |
|---|---|---|---|---|---|
| `qingmu-a1` | 机器人下方 | 机器人右侧 | 机器人后方 | 竖直安装 | 当前使用飞特 |
| `qingmu-b1` | 机器人后方 | 机器人右侧 | 机器人上方 | 水平安装 | 待确认 |

用户明确这两个型号分别采用表中的固定安装方式，不作为可任意旋转安装的通用型号处理。两组轴向均满足右手系。

### 坐标转换的开发基准

设板卡向量为 `(sx, sy, sz)`，机体向量为 `(bx, by, bz)`：

- A1：`(bx, by, bz) = (-sz, -sy, -sx)`。
- B1：`(bx, by, bz) = (-sx, -sy, sz)`。

上述映射用于明确安装旋转的方向和轴符号，是后续单元测试的基准，不是仅修改欧拉角显示的方案。实现时应对角速度、姿态四元数和投影重力执行一致的完整旋转；四元数需遵循现有传感器到机体安装旋转及机体到世界姿态约定，并验证旋转复合顺序。这里不下发生产配置或启用运动。

### 开发必须纳入的要求（部分已实现，以上方最新进度为准）

1. **型号与安装预设绑定**：已知型号自动解析固定安装旋转，正常 Studio 界面只读展示轴向，不要求用户输入 `mount_wxyz`，也不提供与固定安装约束冲突的自由旋转选项。未知型号不得静默套用 A1、B1 或单位旋转。
2. **保持解耦**：区分型号、驱动身份、通信协议和安装预设；型号目录/适配层负责这些差异，控制算法只消费统一机体坐标输入。不要将型号判断散落到策略代码中。共享总线仍只有 robotd 一个访问所有者。
3. **配置链路完整**：Studio 选择型号，经 Agent/协议契约持久化并安全应用，由 robotd 回报实际生效型号、驱动、安装预设及健康状态。必须区分请求值、加载值和生效值；需要重启时明确提示，不在运动中静默切换。型号不可自动识别时允许明确人工选择，不把 PING 兼容型号号当成可靠识别。
4. **处理现有参数迁移**：首批代码原要求显式 `mount_wxyz`；现已加入 A1 自动预设和一致性校验，但尚无 Studio 配置闭环。型号预设优先，历史显式旋转仅在无型号时直接使用；已知型号若携带不一致旋转，应明确报错或要求迁移确认，禁止叠加两次安装补偿。保留旧 embedded/独立 IPC 的既有语义。
5. **标称映射与机体对齐标定组合**：型号预设描述已知板卡轴向和名义安装旋转；多姿态机体对齐标定用 robotd 发布的重力向量估计当前坐标到机体坐标的三维修正，控制输入使用“修正 × 型号名义映射”。标定不是零偏校准，也不直接改写传感器内部坐标。静止单姿态不足以确定完整旋转；采集须覆盖立正、前倾、后倾、左倾、右倾，并检查稳定性、倾斜幅度、反向关系和旋转轴一致性。重复标定需对当前有效修正做增量复合，不能直接覆盖为相对旧输出帧的变换。
6. **可追溯与版本管理**：安装预设应随型号描述/契约进行版本管理，状态及诊断能追溯实际预设版本。B1 在协议和解码能力确认、构建及测试通过前，不得标注为已支持或可直接启用。

## 1. 本次发现

用户确认当前设备是工作区 `others/IMU-DXL`，与舵机共享 TTL 总线，而不是独立 I²C/IIO IMU。解耦目标是型号、解码、传输和控制算法分层，不是强制所有 IMU 由 Agent 独立打开接口并通过 IPC 传入。

证据来自该设备的 README、`docs/PROTOCOL.md`（1.2）、Python/Rust SDK，以及当前 `duck-control/src/imu.rs`、`bus.rs`、`bus_feetech.rs`。设备资料不是部署操作授权；复用 SDK 源码前需核实许可证。

| 项目 | IMU-DXL 设备资料 | 当前差异和影响 |
|---|---|---|
| 接口 | 单线半双工 TTL，1 Mbps，ID 200，只读虚拟舵机 | I²C/IIO 未探测到不能证明它不存在 |
| 协议 | 飞特 SCS/STS、Dynamixel 2.0 | 当前飞特后端仍以总线无 IMU 为前提，缺接入路径 |
| 飞特读取 | 地址 56、长度 15：核心 12、8 位采样序号、状态、保留 | 不能当成舵机反馈寄存器解码 |
| Dynamixel 读取 | 地址 124、核心长度 12；地址 143 读取状态 | 同 ID、地址和长度不代表与旧板解码兼容 |
| 角速度 | int16 小端，raw / 16.4 为 °/s | 旧板为 raw * 0.0175 °/s，直接复用会得到错误比例 |
| 四元数 | binary16 XYZ，恢复非负 W 并归一化 | XYZ 全零可以是有效单位姿态，不能照搬旧板非零初始化判断 |
| 就绪 | 状态 bit 0 为 1 表示未就绪 | 包到达或累计帧数不能代替设备就绪状态 |
| 安装方向 | 板卡轴需通过固定安装旋转转换为机体坐标 | 旧板默认安装角不能直接复用 |
| 自动识别 | 首个有效帧选择协议，连续 20 秒无有效通信后重新自动识别 | 必须跟随同总线舵机协议，禁止两进程交替协议探测 |

PING 型号 1030 是兼容发现标识，不是 IMU-DXL 唯一身份。近期使用用户明确选择的硬件配置，并校验协议应答，不能只凭该型号号自动确认设备。

## 2. 修订架构

```text
共享舵机总线：
IMU-DXL + 舵机 → 唯一总线调度者（近期为 robotd）
                    ├─ 舵机解码 → 关节数据
                    └─ IMU-DXL 型号适配 / 安装变换 → 统一 IMU 输入

独立接口：
I²C / USB / 独立串口 IMU → 型号驱动 / 发布者 → 现有 IMU IPC → 统一 IMU 输入

统一 ImuSource 边界 → 控制算法 / 策略 / 安全状态
```

统一输入沿用机体坐标系、角速度 rad/s、机体到世界的 WXYZ 四元数和投影重力，并携带可观察的 ready、新鲜度、错误原因及型号/驱动身份。具体类型与接口版本在实现中确定；不声明当前已经存在新的同名配置或 API。

近期保留 robotd 为共享串口唯一所有者，型号适配器不自行打开串口；Agent/Studio 只选择、应用配置和读取状态。维护接管必须明确交接，禁止两个进程同时轮询。独立仓库不等于每型号必须独立进程：共享总线适配可以是独立模块/库，控制算法不含型号分支。

现有 Python 驱动包不能直接成为 Rust 的热加载模块。跨语言包形式、发布和接口版本另行定义；不得承诺安装任意 Python 包后 robotd 自动获得该驱动。

## 3. 近期修改方案（待实施）

### 配置与型号选择

- 区分传输来源、型号驱动 ID、总线协议、设备 ID、安装旋转和超时；实际字段需与参数注册、校验和状态回读一起实现。
- IMU-DXL 使用明确型号身份，不复用旧 imu_to_dxl 标识；旧 embedded 仅代表原兼容实现，不是通用总线 IMU 驱动。
- 管理层显示 requested、loaded、effective 状态和重启要求；不能安全热切时，先停控制再重启应用，不静默切换来源。

### 解码与总线调度

- 独立解码核心 12 字节，raw/16.4 后转 rad/s；校验有限值，恢复 W、归一化，并进行完整四元数/向量安装变换，不只交换欧拉角。
- 飞特读取 15 字节完整块，处理状态和 8 位采样序号回绕、断线/重启。静止姿态字节可相同，不能仅按数值不变判 stale。
- Dynamixel 核心块与地址 143 的 ready 状态都要处理；明确状态轮询周期和有效期，状态未知不得当作 ready。没有可靠采样计数时应如实报告新鲜度可观测性限制。
- 分别报告超时、校验错、未就绪和样本过期；控制故障策略需实际验证，不能仅改变 health 标签。
- 先用 READ/SYNC_READ 验证正确性。FAST_SYNC_READ 后续再优化：须满足 ID 200 首位、累计 CRC 和无字节填充等限制，不能假设当前库已支持。

## 4. 测试标准修订

[现有测试记录](../test-plan/imu-decoupling-validation.md) 保留原始事实，不能改写成通过。其无 ID 200 要求只适用于独立 IPC 场景，不适用于当前共享总线 IMU-DXL。接下来按不同拓扑增加测试，不用一种路径证明另一种。

1. 纯解码：已知报文、正负角速度/比例、单位姿态 XYZ=0、binary16 边界与 NaN/Inf、量化误差、未就绪、计数回绕、安装旋转。
2. 传输：碎包/粘包、噪声、错误 ID/长度/CRC、超时重试、舵机和 IMU 应答不混淆，不向 IMU 下发舵机写操作。
3. 共享总线：飞特和 Dynamixel 分别覆盖；单一串口所有者、维护接管、15 舵机和 IMU 同时读取，测量控制周期耗时与 jitter。
4. 安全状态：启动未知、未就绪、断线、重连和恢复；旧帧不维持 ready，不自动回退另一来源，验证实际运动安全策略。
5. 回归：独立 IPC 无 ID 200 工作、publisher 重启/stale/非法帧/socket 权限；旧 embedded 保留原比例和安装参数。
